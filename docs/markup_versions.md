# Версии разметки

## Рядом с видео — история версий

У каждого видео своя история версий разметки рядом с видео:

```
<папка видео>/
  line1_cam5.avi
  line1_cam5.markup.json        ← файл разметки рядом с видео; всегда равен текущей версии
  line1_cam5_jsons/             ← версии этого видео
    versions.json               ← список версий и номер текущей
    v1_20261102-153000.json
    v2_20261102-154512.json
```

Число версий не ограничено. Файл `<имя видео>.markup.json` читают все, кто пользуется разметкой, —
он всегда равен **текущей** версии.

### Сохранение в редакторе

| Кнопка | Что происходит |
|---|---|
| **Сохранить** | в то, что открыто: версию `vK` — перезаписать (новая не создаётся); боевую — в боевой JSON; файл, изменённый вне версий, — новой версией |
| **Сохранить как новую версию** | правки сохраняются новой версией `vN+1`; она становится текущей |
| **Сохранить в боевой JSON** | перезапись боевой разметки с подтверждением; версии рядом с видео не меняются |

К версии можно написать комментарий — поле в окне подтверждения.

### Первое сохранение и изменения вне редактора

- Файла рядом с видео не было — первое сохранение создаёт `v1`.
- Файл был, а версий нет — его содержимое сначала сохраняется как `v1` («исходная»), затем правки.
- Файл изменён не через редактор (не равен текущей версии) — перед записью его содержимое сохраняется
  отдельной версией («изменена вне редактора»). Ничего не теряется.

### Список версий

В редакторе версия выбирается в переключателе на кадре: «Боевая | Рядом с видео | vN ▾» (комментарий
версии — в подсказке). Список: ★, номер, комментарий, время, «текущая».

- **щелчок по строке** — версия становится текущей (файл рядом с видео становится равен ей) и открывается;
  остальные версии не меняются, изменённый вне версий файл сначала сохраняется отдельной версией;
- **Сравнить** — контуры версии пунктиром поверх открытой и сводка отличий по объектам;
- **★** — отметить версию как избранную.

В панели карточки видео — тот же список: выбранная версия сразу становится текущей и показывается на кадре.

### versions.json

```json
{
  "format": 1,
  "current": 2,
  "versions": [
    {"number": 1, "file": "v1_20261102-153000.json", "created": "2026-11-02T15:30:00+03:00",
     "updated": "2026-11-02T15:30:00+03:00", "hash": "<sha256>", "origin": "editor",
     "based_on": null, "source": "production", "comment": "из боевой", "pinned": false}
  ]
}
```

- `origin` — `initial` (файл до истории), `external` (изменён вне редактора), `editor` (сохранён из редактора),
  `sync` (записан синхронизацией с боевой — приложением-хозяином через `VersionStore.save(..., origin=VersionOrigin.SYNC)`);
- `based_on` — номер версии, из которой сделана правка; `source` — какая разметка была открыта (`sidecar`/`production`);
- `hash` — SHA-256 содержимого файла версии.

## Боевая — без истории

Боевой JSON перезаписывается целиком. Перед перезаписью прежнее содержимое копируется в
`<ключ>.json.bak` рядом с ним (одна копия, следующая перезапись её заменяет).

## Защита от чужих правок

Редактор запоминает, каким был файл при открытии. Если к моменту записи файл изменили (другая программа,
другое окно редактора), запись отклоняется и редактор предлагает:

- **Перечитать файл** — правки в редакторе теряются;
- **Всё равно записать** — для разметки рядом с видео чужие изменения сохранятся отдельной версией.

## API

| Метод | Назначение |
|---|---|
| `GET api/versions?video=` | версии и текущая |
| `GET api/markup?video=&variant=sidecar&version=N` | содержимое версии |
| `POST api/save` | `mode`: `new` / `overwrite`, `base_version`, `comment`, `expected_hash`, `force`; при чужих правках — `409` |
| `POST api/versions/current` | `{video, number}` — сделать версию текущей |
| `POST api/versions/update` | `{video, number, pinned?, comment?}` |

Из Python: `VersionStore(video_path)` — `history()`, `load(n)`, `save(...)`, `make_current(n)`, `update(n, ...)`.
